## Sequential implementation steps

1. Bind the same-origin B04 API to F02's versioned `RunView`, event-page,
   command/error, assessment-summary, and optional evaluation-summary contracts.
   Use sessions, CSRF for commands, stable errors and server-assigned IDs. U02 may
   merge before Q05; unavailable measurement is explicit, never fixture fallback.

2. Implement cursor polling with no overlapping requests, bounded backoff, event/claim deduplication and protection against stale revisions. Browser refresh/reconnect reopens the same persisted run without changing attempts or restarting deadlines.

3. Connect start/reopen, Slack review navigation, and guarded reconciliation.
    Handle validation, unauthorized, expired-session, offline, stale-response,
    monitor-unavailable and failed-partial states without replacing last-known
    product state. Browser commands cannot supply trusted approvals, observations,
    labels or provenance. Authorize every evidence/report reference server-side;
    an authorization failure is an API error, not report availability.

4. Show saved raw critical counts, M1-M7 numerator/denominator or N/A, census/gaps,
   mode/version/cutoff/watermark, product status, trace/process result, expected/
   actual result and original-proposal quality independently. Include unverified
   claims, missing labels and unrun counts. A missing Q05 report stays unavailable;
   U03 is not needed for this basic evidence surface. Perform no browser arithmetic.

5. Test refresh, duplicate start, overlapping-poll prevention, out-of-order events,
   monitor outage, session expiry, authorization failure, stale run/report revisions,
   completed-but-unverified status and continuation after browser closure. Exercise
   fake S1/S2/S3 through assembled HTTP, preserve one run/evaluation identity and
   model-call count, and compare rendered values exactly with Q05's saved report.

## Reviewed implementation and verification receipt

The default console uses same-origin authenticated B04 commands, run reads,
opaque event cursors, and incremental trace reads. Commands include only the
frozen intent fields and session CSRF header. Approval stays in Slack. Partial
reconciliation shows the actual server command disposition, including
`not_eligible`, without assuming execution or completion.

Polling is sequential with bounded backoff. Run, evaluation and runtime identity,
event order, and run/report/assessment revision floors survive transient outages.
Refresh persists only the run ID and opaque event cursor; browser closure cancels
reads, never backend work. Session expiry and forbidden access stop polling until
an explicit authenticated reconnect. Known product/effect state remains visible.
The summary renders saved counts, measurements, census, gaps, versions and
provenance without arithmetic. Missing values remain unavailable.

U01 fixtures are loaded only through explicit `/?preview=1` or the test prop.
There is no production error fallback to synthetic data. Two minimal U01 test
joins were reviewed by the frontend owner: `tests/app/console.test.tsx` preloads
its explicit preview, and `tests/e2e/console-fixtures.spec.ts` visits the preview
URL and waits for its lazy entry before keyboard interaction. These are the only
implementation-path exceptions; dependencies, shared schemas, server modules and
styles were not changed. This receipt, branch handoff and Global Scale are
integrator documentation updates.
