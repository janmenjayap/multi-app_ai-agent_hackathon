## Sequential implementation steps

1. Bind the same-origin B04 API with sessions, CSRF for commands, stable errors and server-assigned IDs. Use F02's optional report projection so U02 can merge before Q05; unavailable measurement is an explicit state, not fixture fallback.

2. Implement cursor polling with no overlapping requests, bounded backoff, event/claim deduplication and protection against stale revisions. Browser refresh/reconnect reopens the same persisted run without changing attempts or restarting deadlines.

3. Connect start/reopen, Slack review navigation, and guarded reconciliation. Browser commands cannot supply trusted approvals, provider observations, semantic labels or evidence provenance. Use server authorization for every evidence/report reference.

4. Show saved raw counts and mode/version/cutoff, product status, trace/process result, expected/actual result and original-proposal quality independently. Include unverified claims, missing labels and census unrun counts when reports arrive. A missing Q05 report stays unavailable; U03 is not needed for this basic evidence surface.

5. Test refresh, duplicate start, out-of-order events, monitor outage, stale report revisions, completed-but-unverified status and server continuation after browser closure. Join with real B04 endpoints, preserve one run/attempt identity, and add actual report verification after Q05 joins at release.

Use the [LLM call guide](../07-agent-spawning-and-llm-integration.md) and
[app transport guide](../08-mcp-api-and-external-app-integration.md) with the
[F02 handoff contract](../05-contracts-and-handoffs.md). This commit owns:

- `web/api/client.ts` calls the authenticated backend `POST /api/runs`, run/event reads and `POST /api/runs/:id/reconcile`. Only the backend's B04/R01 path invokes A01 models and I01–I05 app adapters.
