## Sequential implementation steps

1. Freeze the actual code/dirty-state hashes, package/runtime/model/prompt/policy/schema/evaluator/fixture versions, suite census hash, enabled roles, optional capabilities, attempts and report cutoffs in `docs/release-manifest.json`. Preserve the v1 monitor/checker receipts as historical scope.

2. Verify the exact release through clean setup, server/web builds, checker,
   monitor, application, component/accessibility, browser and scenario checks.
   Read Q05's full census, original proposal reviews, per-claim verdicts,
   independent provider fields and failed/unrun cases. A green test command,
   screenshot, or zero v1 premature counter cannot close agent reliability.

3. Produce `docs/evaluation-summary.md` with M1–M7 raw denominators by mode/version, claim verdict coverage, zero-label/unverified results, planned versus attempted coverage, safety violations, and links to restricted evidence. State any deferred successful-recovery baseline and incomplete G5 coverage explicitly.

4. Write `docs/reliability-brief.md` around the three proven axes: original AI decision quality, real runtime/trace control checks, and frozen expected-versus-independent actual app state. For each claim name the source release, exact scenario and artifact/review receipt. Document the v2 false-completion union and emission-time limits if claiming that capability.

5. Rehearse `docs/demo-runbook.md` in a clean authenticated browser showing the
	actual S1 input/stages/plan/Slack link/artifacts/readbacks, S2 ID reuse without
	new model work, a safe block/stale approval or tamper detection, and the
	measured report. Show product status separately from pending/unverified
	assessment. Verify authorized links, redaction, session expiry, keyboard/focus
	behavior, readable 1440x900 recording layout and 375x812/768x1024 no-overlap
	views. Keep the two-minute video accurate, usable with optional LangSmith/U03
	disabled, and privacy-safe.

6. Update README and Global Scale only against reviewed capability/gate evidence. G1–G6 remain open until their individual requirements pass; a narrower demonstrated release can leave G5 open. Changes after freeze require relevant reruns and new evidence versions.

7. Check exact submission instructions, links/access, recording duration/playback and setup from the frozen release. The submission owner delivers the package and records confirmation separately from implementation/test evidence. This documentation planning task does not itself submit or publish anything.
