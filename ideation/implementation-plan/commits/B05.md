## Purpose and current state

**PLANNED.** The monitor can assess supplied approval events, but no implemented
product reads Slack decisions or enforces them. Add authentic review/decision
ingestion and fresh-source validation as prerequisites to protected execution.

## Allowed paths

`src/server/policy/approval.ts`, `src/server/policy/freshness.ts`;
`src/server/workflow/review.ts`, `src/server/workflow/approval-wait.ts`;
`tests/app/approval.test.ts`. Consume the Slack adapter and source-read contracts;
do not edit adapter credentials/transports, shared contracts, or root packages.

## Sequential implementation

1. Implement exact review publication/reconciliation from B03's immutable plan.
   Separate this effectful node from the pure graph interrupt/wait node, and
   independently read the posted review before accepting decisions.
2. Ingest Slack replies through I04 and validate workspace/channel/thread,
   authorized human, unique hash prefix/full hash, revision, message integrity,
   expiry, and decision. Persist authoritative decision references through B01.
3. Make rejection final for its revision; ignore duplicate/out-of-order/bot/
   unrelated replies and invalidate edited/deleted approvals. A resume reference
   wakes work, then server code independently reloads and validates authority.
4. Persist waiting deadlines, release the worker, and revalidate complete source
   selection on approval/resume. Relevant source corrections require a new plan
   and approval on the same run; unavailable reads cannot authorize execution.
5. Add adversarial wait/restart/decision tests in this commit. Cover families
   6/7/15, expiry, edited/deleted replies, duplicate wakeups, and S3 correction.
   Assert no protected dispatch occurs from any invalid decision.

## Authentic approval receipts and dispatch handoff

The [reliability plan](../06-agent-reliability-implementation.md) requires enforcement plus observable evidence, not supplied approval Booleans.

1. Store approval evidence from fresh I04 thread reads: workspace/channel/thread/message IDs, actual actor identity/type, content digest, edit/deletion state, complete retrieval receipt, exact plan hash/revision, expiry and checked-at observation window.
2. Bind approval and source-freshness decisions to the specific guarded dispatch scope. Return a server-owned receipt/reference that B06 revalidates before each mutation; an earlier successful approval check cannot authorize later writes after expiry or source drift.
3. Emit accepted/rejected/invalidated/rechecked decisions through the B01 transaction seam, including reason codes and sanitized receipt references. Keep the raw approval body in restricted storage when needed for review.
4. A wakeup reference carries no authority. On resume, fetch the latest complete source and approval observations; if Slack is unavailable, the actor is unauthorized, the approved reply changed, or rejection already won for that revision, stop before protected dispatch.
5. Extend tests with a forged imported approved flag, correct hash in the wrong thread, bot impersonation metadata, approval deletion between effects and a clock-boundary expiry immediately before dispatch.

**Additional acceptance:** every dispatchable receipt can be traced to an authentic provider observation and exact immutable plan, and every invalid case has zero subsequent protected calls. Q03 checks those references; Q02 later collects its own Slack history and does not accept the producer's declaration alone.

## Agent, LLM and external-app integration

Use the [LLM call guide](../07-agent-spawning-and-llm-integration.md) and
[app transport guide](../08-mcp-api-and-external-app-integration.md) with the
[F02 handoff contract](../05-contracts-and-handoffs.md). This commit owns:

- `workflow/review.ts` uses I04 to post/reconcile the exact plan in the configured Slack channel and retrieve it. `approval-wait.ts` persists a pure wait; on wake, `policy/approval.ts` freshly reads the authorized human's decision through I04 and binds workspace/channel/thread/revision/hash.
- `policy/freshness.ts` consumes refreshed I02/I03 evidence supplied through the injected source-reader seam. Source changes invalidate approval and route through R01's guarded revision policy; they do not authorize an ad hoc model rerun or revised payload.
- No LLM judges approval. REST/MCP request consent is distinct from the business decision. Test edited/deleted Slack decisions, wrong account/thread, unavailable thread reader and zero model calls during wait/resume of an unchanged approved plan.

## Do not

- Accept a UI flag, worker event, or graph resume payload as proof of approval.
- Revive a rejected revision with a late approval, silently extend expiry, or
  authorize work from incomplete/failing source or Slack reads.
- Perform HubSpot/Gmail/GitHub protected mutations in review/wait code.
