## Sequential implementation steps

1. Join Q04's frozen suite census to all registered/attempted records and Q03's versioned assessments; retain unmatched planned slots as unrun. Show planned, setup-failed, registered, attempted, assessed, passed, failed, pending, unverified, and unrun counts without treating these overlapping operational/assessment counts as one additive partition. Mandatory preflight/S0 collection occurs before registration; those failures are setup-failed census entries, not M1/M7 attempts. Failures after registration stay attempted and cannot be relabeled as setup. Preserve modes/versions and original attempt IDs across resumes.

2. Extend R01's minimal trusted review receipt input with the richer independent human review workflow in `labels.ts`; preserve F02/B01 receipt identity and provenance. Store reviewer identity/kind, review timestamp, source snapshot/output digests, original proposal/stage identity, per-claim support verdict and source fields, required-content verdicts, short reasons, uncertainty, and correction/supersession references. Preserve earlier labels and original outputs. Enforce actual reviewer provenance; a synthetic `reviewerKind: human` object does not become a human review.

3. Keep M7's first unedited analyst/drafter proposal denominator intact when outputs are missing, invalid, uncertain, or corrected. Separately report selected-plan quality, regeneration/human intervention, auditor misses and false blocks. Count individual unsupported factual claims only when claim-level labels exist; disclose the legacy proposal-level proxy otherwise. Zero actual labels yields unverified semantic results.

4. Extend the existing aggregation engine only for the v2 contracts. Consume Q03 claim verdicts; aggregate `prematureSuccessClaims`, `outcomeContradictedCompletionClaims`, their deduplicated `falseCompletion` union, all success claims and unverified claim coverage. Never reinterpret v1's premature-only counter as comprehensive false completion or recompute claim truth in report code.

5. Preserve M1–M7 raw units, all eligible attempted denominators, first logical calls versus tool attempts, censored latency, recovery classes, and null rates for zero denominators. Independently confirmed M3 acknowledgements require Q03's corroborated actual fields. Keep all release-critical predicate failures visible even when an aggregate looks high.

6. Save reproducible machine-readable and human-readable reports through `report.ts` and `tools/evaluations/report.ts`: source release/dirty-state hashes, versions, census hash, attempt IDs, assessment watermark/cutoff, evidence/label revision references, raw numerators/denominators and gaps. Produce F02's authorized `EvaluationSummaryView` plus detail references: stable report/cohort IDs, report revision, evaluator/manifest versions, evidence mode, census, M1-M7 units and eligibility, critical counts, gaps, cutoff/watermark and explicit N/A/unverified states. Keep private raw records restricted and return explicit pending/unavailable/unauthorized responses instead of empty reports.

7. Add hand-calculated cohort tests for a failed original proposal plus successful correction, 18-family census with unrun/setup-failed cases and S0-before-registration denominators, replayed measurements, 0/0 rates, absent labels, v1/v2 separation, claim overlap without double count, correct-at-emission/later-drift, uncorroborated acknowledgement, and censored attempts. Add accepted saved-summary/detail examples whose displayed values U02/U03 can compare byte-for-byte. Preserve baseline monitor/checker tests; no simulated cohort becomes a live result.

- Do not rewrite the tested aggregation engine, equate checker assertion counts with scenario runs, or blend modes/versions into one score.
- Do not count human approval as original proposal correctness, synthetic human labels as actual review, safe escalation as recovery success, or proxy counters as individually measured claims without disclosure.
