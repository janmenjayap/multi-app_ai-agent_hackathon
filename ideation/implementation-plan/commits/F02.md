### Frozen interface and consumer notes

All new persisted/application/API envelopes use numeric `schemaVersion: 2`.
Unsupported versions fail parsing. `monitor-v1` and its schema-1 readers retain
their existing meanings; `monitor-v2` names the new evaluation contract only,
not an implemented evaluator. No database, route handler, transport, role runner,
workflow, scenario oracle or UI implementation is supplied by F02.

- `domain.ts`: shared IDs, v1-compatible app/role/mode/status primitives,
  complete/incomplete page receipts, selection, immutable incident and plan,
  Slack decision shape, effect state/outcome, logical references and canonical
  hashing. A denied read is `incomplete` with `reason: denied`; consumers cannot
  interpret it as a complete empty result. Plans contain task/note/draft per
  selected commitment, followed by one incident comment and one final Slack
  summary. Destination references preserve exact target kinds and ordering.
- `agents.ts`: the three `(input, context, dependencies)` function interfaces,
  stable run/revision/role invocation keys, F01-compatible model budgets, exact
  draft selected-set coverage, original-source projections and auditor omission
  findings. `parseRoleInput` verifies the canonical input digest and budgets;
  consumers validate output citation IDs with `parseIncidentAssessment`,
  `parseDraftProposal(value, selectedIds, sourceFactIds)` and `parseAuditVerdict`.
  Citation existence does not establish semantic support.
- `adapters.ts`: constructor-bound accounts, narrow readers, Slack coordination,
  protected writes, provider receipts and optional MCP mapping metadata. Reads
  preserve malformed business fields/extra observed recipients for comparison.
  Mutations have a single dispatch attempt; reconciliation owns any later action.
  MCP metadata grants neither runtime availability nor Slack business approval.
- `events.ts`: v2 UTC/process/boot/monotonic envelopes, spans, model/provider
  attempts, causal references, retries and jobs. Complete-history batch validation
  rejects orphan/mismatched spans and attempts; missing results remain unresolved.
  `parseEventV2Compatibility` alone accepts legacy `attemptId`, rejecting
  conflicting aliases without manufacturing missing telemetry.
- `evaluation.ts`: original model outputs, append-only correction/review records,
  untrusted imported observations, manifests, account-bound ID/content bindings,
  registration/census, claim sets and ratio/latency metrics. The strict
  `CompletionClaimSchema` is an emission gate; `ObservedCompletionClaimSchema`
  retains premature or unsupported claims for evaluation. Observed tool events
  likewise preserve forbidden actions without adding adapter capabilities.
  An imported mode or human-looking label is never authenticated provenance;
  B01/Q02 must implement trusted ingestion and actual operator-review binding.
- `api.ts`: versioned run/event/trace/assessment/report/command/error projections,
  fixed nine-stage pipeline, exact authorized plan payloads, field comparisons,
  redacted references, revision checks and explicit absence. Product completion
  can coexist with pending or contradicted independent assessment. Zero human
  labels cannot pass, 0-of-0 is N/A, M6 retains latency/censoring semantics, and
  the browser can submit only start/reopen or reconcile intent. Authentication,
  CSRF and per-reference access checks remain B04's server responsibility.

`parseImmutablePlan` validates shape and freezes nested data;
`verifyPlanIntegrity` additionally checks normalized UTF-8 content hashes,
canonical request hashes and the plan hash. Request hash material omits its own
digest and expands approved-content references from the frozen plan, while
preserving allowed logical destination substitutions. Plan hash material omits
only `planHash`. Key sorting preserves array order and exact strings; body
normalization is explicitly NFC with LF line endings, without trimming. Golden
vectors cover arrays, Unicode, CRLF and empty fields.

Accepted/rejected examples are in
[`tests/app/contracts.test.ts`](../../../tests/app/contracts.test.ts), including
all required browser state distinctions, relational failures and compile-only
capability/identity/trust checks. These establish contracts; Q01 must independently
author business expectations and synthetic scenario truth.
