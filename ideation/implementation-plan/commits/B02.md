## Sequential implementation

1. Parse allowlisted GitHub issue identifiers into immutable repository/issue
   identity. Reject unsupported input instead of fetching arbitrary pasted URLs.
2. Validate typed production/impact/service/environment evidence and required
   completeness metadata. Distinguish invalid/incomplete source retrieval from
   a complete valid empty eligible set.
3. Select active exact-service commitments with the frozen inclusive UTC horizon;
   resolve company, owner, and the unique explicitly designated contact by ID.
   Preserve reasons for inclusion/exclusion and block ambiguous/malformed affected rows.
4. Pin source identity and detect relevant service/environment edits without
   opening another run/effect namespace. Return typed safe block, failure, no-op,
   or selection outputs; do not perform provider writes.
5. Add Q01-backed boundary and adversarial tests in the same commit: exact
   time edges, missing owner/contact, ambiguity, closed/nonproduction input,
   failed second page, and edits to a known issue identity.

## Decision-quality evidence and safe-outcome acceptance

Reliability includes correct safe decisions as defined in the [detailed implementation plan](../06-agent-reliability-implementation.md).

1. Return the source snapshot IDs/digests, completeness receipts, frozen reference time and policy version with every selection result. Preserve excluded candidates and explicit reasons sufficiently for Q04 to compare the decision with its independent frozen oracle.
2. Do not let a source-controlled instruction, model suggestion, failed page or ambiguous designated contact alter server-owned identity policy. Complete zero-impact, safe block, source failure and eligible selection remain different outputs.
3. Make the output suitable for B04's canonical decision event without giving this pure module persistence or network authority. A complete empty selection supplies the source/completeness and selection-policy receipts needed by the typed no_affected claim; B07 still checks absence predicates. That path creates no approved plan or required final Slack artifact. B03 consumes nonempty selected IDs and source versions; it cannot replace policy failures with model confidence.
4. Add paired fixtures with identical first-page data but different page-two completeness, and with the same incident identity but changed source version. Assert the correct disposition and explanation as well as the selected IDs.

**Additional acceptance:** Q04 can reproduce every inclusion/exclusion from the frozen facts and policy version. The ambiguous-contact leg yields the expected block with no protected effects; a repaired source yields a new selection/plan revision within the same business run. These tests establish deterministic decision behavior; actual analyst/drafter quality still needs A01–A04/Q05 evidence.
