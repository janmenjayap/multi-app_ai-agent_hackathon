## External-app integration to implement in this commit

Implement the [HubSpot routes, properties, and access mapping](../08-mcp-api-and-external-app-integration.md#4-hubspot--i03)
in `src/server/adapters/hubspot.ts` through I01 at `https://api.hubapi.com`.
Read `/crm/v3/objects/tickets`, exact `/companies/{id}` and `/contacts/{id}` under
the same object prefix, and `/crm/v3/owners`; request explicit source properties
and complete associations. Tasks/notes use `POST /crm/v3/objects/tasks` and
`POST /crm/v3/objects/notes`, their individual `GET` routes, and complete marked
enumeration. Create with exact approved owner/due/content and company/commitment
association IDs; no protected update/delete or guessed contact selection.

F01 validates `PG_HUBSPOT_ACCESS_TOKEN` and `PG_HUBSPOT_PORTAL_ID`; R01 supplies
credentials and the verified schema/association mapping through composition.
Preflight records the chosen API family and actual endpoint permissions:
company/contact reads, `tickets`, owners read, and activity creation permissions.
The documented v3 task-create scope is `crm.objects.contacts.write`, which is
broader than task-only. Verify note and association capabilities as well; do not
invent `tasks.write`/`notes.write` scopes or claim provider-enforced task-only auth.

R01's `read_hubspot_candidates` node uses this adapter before calling B02's pure
selection policy. B06 creates each approved task/note; B07/Q02 independently read
actual fields and paginated relationships, including protected Beta. Agents
receive projected source facts only; no LLM call or model-callable CRM tool occurs
here. Optional MCP uses reviewed per-method mappings behind the same boundary.

**Handoff gate:** fixtures cover absent properties, wrong immutable owner/contact,
association pagination and ambiguity. `tools/smoke/hubspot.ts` must prove the real
account mapping and both task/note creation plus independent field/association
readback; reading a company or receiving a create acknowledgement is insufficient.
