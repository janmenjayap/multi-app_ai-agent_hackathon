## Sequential implementation steps

1. Implement prompt.ts with the scoped technical evidence projection and versioned instructions distinguishing supported facts from candidate changes. Exclude contact selection, credentials, and any source instruction claiming tool authority.
2. Implement validate.ts for role output shape, citation membership, required uncertainty, and mechanically testable fields; keep semantic support distinct from mere source-ID existence.
3. Implement index.ts through A01 with one logical invocation per plan revision and immutable output references. Preserve malformed or corrected first attempts in B01 rather than replacing them.
4. Add independent weak-evidence, contradictory-source, absent-citation, and source-injection tests in analyst.test.ts. Verify a recent deployment cannot automatically become a proven cause.
5. Run targeted tests and F01 build/typecheck. When actual model outputs are available, obtain independent human labels for causal overclaiming and missing uncertainty, preserve corrections, and hand the typed assessment to R01.

## Exact analyst invocation and external-evidence boundary

Follow [agent/LLM integration](../07-agent-spawning-and-llm-integration.md).
Export `analyzeIncident(input: AnalystInput, ctx: AgentInvocationContext, deps)`
from **analyst/index.ts**, returning `AgentCallResult<IncidentAssessment>` using
F02 schemas. R01's **src/server/workflow/nodes.ts** calls it from
`analyze_incident` only after complete source collection and a valid nonempty
B02 selection. B04 schedules the graph; it does not call this role from HTTP.

**The actual request path is** graph node → `analyzeIncident` → A01
`invokeRole` in `agents/runtime.ts` → `dispatchStructured` in `agents/model.ts`
→ `ChatOpenAI`/OpenAI Responses. `analyst/prompt.ts` supplies only bounded
GitHub issue/commit/deployment/workflow evidence, stable citations and uncertainty
instructions. `analyst/validate.ts` validates the parsed result through the A01
validation seam; it cannot overwrite the raw response already saved by A01.

I02 reads GitHub through the [external-app adapter boundary](../08-mcp-api-and-external-app-integration.md);
R01 projects those immutable snapshots for this role. Do not add MCP, GitHub API,
HubSpot contact lookup, `bindTools`, or generic HTTP calls inside the analyst.
Credentials and actual source acquisition stay outside the prompt and role.

Use `role=analyst` and the stable run/revision/role invocation key. Reuse a matching
validated assessment after restart; source, prompt, schema or model changes
require a new revision. `OPENAI_MODEL_ANALYST`, when configured, is resolved by
A01 from F01's validated configuration; this role must not read env or build a
second model client. Return original-output references for R01/B03/Q05 alongside
the typed assessment. R01 supplies the assessment to A03 only after validation.

**Additional invocation acceptance:** a spy A01 runtime receives one analyst
request with the expected role/schema/version and no contact/credential context;
an invalid source citation fails and retains the first result. The role can be
tested with an injected model stub. R01 owns integration assertions that empty
or invalid selection produces zero model calls and analyst failure prevents
drafter/auditor dispatch.

## First analyst output and independent quality review

Apply the [reliability plan](../06-agent-reliability-implementation.md)'s agent decision-quality axis.

1. Bind the original assessment and each factual clause/citation to immutable A01 output and source-version references. Keep unsupported causal claims, omissions, malformed outputs and explicit unknowns visible for review, even when deterministic validation later rejects them.
2. Mechanical validation checks shape/reference membership and enforceable constraints. Actual entailment, completeness and honest uncertainty require Q05's source-based human labels; the presence of a valid citation or a clean auditor verdict is insufficient.
3. Test paired fixtures in which the same valid source ID supports one statement and contradicts another. Include recent-deployment correlation presented as certainty, contradictory incident updates, stale sources and injected instructions.
4. Handoff the first raw output, parsed proposal, validation findings, any correction chain and input/output digests to B03/R01/Q05. Review labels and reviewer reasons are append-only; corrected output cannot erase the first-proposal quality failure.

**Additional acceptance:** fixtures demonstrate reliable module boundaries, and an actual-model quality claim requires independent labels against the original source snapshot. Missing actual reviews remain unverified, with proposal-level proxy counts kept separate from per-claim semantic findings.
