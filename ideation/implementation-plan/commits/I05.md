## External-app integration to implement in this commit

Implement the [Gmail API/OAuth/MIME mapping](../08-mcp-api-and-external-app-integration.md#6-gmail--i05)
in `src/server/adapters/gmail.ts` and `gmail-mime.ts` through I01. Against
`https://gmail.googleapis.com/gmail/v1/users/me`, use `POST /drafts` with approved
base64url MIME, `GET /drafts` with complete pagination, and
`GET /drafts/{id}?format=raw` for actual headers/body/state. Implement
`findDraftsByEffectMarker` by complete listing plus full candidate retrieval;
custom MIME headers are not assumed to be indexed by Gmail search.

F01 owns `PG_GMAIL_CLIENT_ID`, `PG_GMAIL_CLIENT_SECRET`,
`PG_GMAIL_REFRESH_TOKEN`, and `PG_GMAIL_MAILBOX`; R01 injects the authorized
mailbox client. Prepare Gmail API/consent/client/redirect/offline OAuth setup
through `tools/smoke/gmail.ts` or operator provisioning, not a new product API
route. Writer `gmail.compose` also allows sending at Google: enforce draft-only
methods and egress; never advertise a draft-only OAuth token.

B06 supplies exact approved recipient/subject/body/marker after durable dispatch
intent. B07 independently reads full MIME; Q02 gets separate read capability and,
when authorized, a `gmail.readonly` reader via `PG_GMAIL_READER_REFRESH_TOKEN` for
scoped message/history evidence. Missing operation-history coverage remains
unverified. Analyst/drafter/auditor receive no Gmail capability or credentials;
the draft's text was generated earlier through A01 and is not regenerated here.
Optional MCP must expose sufficient verified draft/MIME reads under the same
contract; an email-summary tool or hosted model tool is not a substitute.

**Handoff gate:** fixtures prove extra recipients/changed MIME/duplicate markers
remain detectable and no send/update/delete method is available. The disposable
smoke proves authenticated mailbox → marked create → complete find → separate
full-MIME readback. It never sends email or cleans up through the worker.

## Sequential implementation steps

1. Define the gmail.ts / gmail-mime.ts seam using F02 and I01: raw full draft records in, all actual mailbox headers, decoded subject/body, draft state, stable IDs, and normalization errors out.
2. Implement MIME normalization without discarding unexpected addresses or silently repairing content. Add fixtures for extra To/Cc/Bcc, encoding and line-ending cases covered by the frozen body contract, changed subject/body, and missing draft state.
3. Implement bounded draft listing plus full retrieval for every marker candidate. Preserve complete/incomplete status and multiple matches; test later-page failure and ambiguous lookup.
4. Implement narrow create/get draft methods accepting exact approved fields. Keep mutation retries disabled; surface unknown outcomes to B06 and add tests proving no send/delete/generic-request capability is exposed.
5. Implement tools/smoke/gmail.ts and later exercise OAuth access, draft creation, marker lookup, and full independent read-back on a disposable mailbox. Run owned tests and F01 build/typecheck; record actual permissions and smoke evidence only when exercised.

## Gmail recipient, content, and non-send evidence

Supply complete provider observations for the [reliability plan](../06-agent-reliability-implementation.md).

1. Preserve full raw MIME response references/digests, draft/message IDs, draft state, every actual To/Cc/Bcc occurrence, subject, decoded text and relevant attachment/part errors. Store observations independently of the requested payload; normalization cannot remove an unexpected address.
2. Bound full draft enumeration and retrieval of every marker match with page coverage and UTC/monotonic observation windows. A list item, cached create response or single empty search does not prove a complete final state.
3. Expose read-only draft and narrowly scoped message/history evidence needed by Q02 where the account permits it. B06 receives only narrow approved creation authority; no send, delete or generic request is made available to the worker.
4. Declare unavailable operation-history/permission coverage explicitly. Absence of a send method plus an unchanged final draft does not alone prove that no external send occurred; Q02 combines collected history and trace evidence and leaves missing coverage unverified.
5. Add duplicate header/folded address, multipart body, unexpected Cc/Bcc, sent/not-draft state, later-page duplicate and acknowledged-but-missing draft fixtures.

**Additional acceptance:** wrong recipient/content/state stays detectable after normalization and a full independent read proves actual draft content. Live smoke IDs/raw MIME remain restricted; sanitized fixtures and their evidence mode cannot be relabeled as authenticated live evidence.
