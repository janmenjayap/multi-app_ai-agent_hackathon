## Sequential implementation

1. Define the deterministic effect order and exact request-template resolution:
   task → note → Gmail draft → GitHub comment, with verification before progressing.
   No model call may rewrite approved payloads.
2. Recheck approval/expiry and source freshness before each remaining mutation;
   atomically claim its stable effect and persist request/attempt intent through B01.
   A persistence failure must prevent dispatch.
3. Resolve prior applied/inflight effects using complete exact-marker/content/
   association reads. Adopt a single exact match; preserve conflicting,
   multiple, human-edited, or unresolved work for explicit review.
4. Dispatch only approved requests and persist known application, known
   nonapplication, or unknown outcomes. Use bounded settling reads for uncertainty;
   do not release inflight claims or create again merely because lookup is empty.
5. Add named race/crash/unknown-result fixtures and tests in this commit:
   concurrent replay, timeout after acceptance, conflicting adoption, expiry
   midway through the batch, and storage failure before dispatch.
6. Join with the injected verifier contract and confirm partial effects retain
   original plan/approval/provider IDs and produce `failed_partial` when incompatible.

## Execution provenance and per-dispatch reliability gate

Use the [reliability implementation plan](../06-agent-reliability-implementation.md) to connect preventive guards with measurable attempts.

1. For every mutation, load the immutable plan and latest authentic B05 receipt, revalidate source/expiry, resolve ApprovedContentRef only from that plan's frozen exact bytes/digest and EffectIdRef only through declared independent bindings, and persist the exact request digest/intent before dispatch. Permit only approved ID/link substitutions. Bind the guard decision, approval/source receipts and provider attempt to the same effect and revision; observed provider text cannot supply expected/requested content.
2. Emit logical-call, dispatched-attempt, transport result, provider result, retry/settling schedule and reconciliation outcomes separately. A timeout records unknown application; a provider-level rejection inside HTTP 200 records failure. The adapter and executor must not both retry.
3. Preserve attempt UTC/monotonic windows and the causal sequence from intent to dispatch to receipt/readback. Provider receipt storage failure after dispatch leaves an unresolved effect for reconciliation; it must not look like a call that never happened.
4. Before the next protected effect, require B07-compatible verification evidence for the preceding one. Preserve partial-state evidence and block full-completion claims while any effect is missing, mismatching or unknown.
5. Add tests for approval invalidation immediately before dispatch, forged success declarations, lost response after provider acceptance, successful transport with failed provider result and an attempted undeclared link substitution.

**Additional acceptance:** join every actual provider call to one durable intent, plan, guard receipt and attempt ID; zero unauthorized or second uncertain creates occur. Hand Q03 the canonical trace, and Q02 the stable run/effect markers for independent reads without sending it precomputed pass verdicts.
