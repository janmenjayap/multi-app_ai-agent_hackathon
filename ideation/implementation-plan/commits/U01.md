## Sequential implementation steps

1. Freeze F02-shaped synthetic fixtures for every state in the frontend guide's
	complete state/error matrix. Include zero human labels, missing provider
	fields, claim contradictions, empty report denominators, offline/session
	errors, stale revisions, and failed partial effects. Label all examples synthetic.

2. Build IncidentInput, StatusBand, EvidencePanel, PlanPanel, and EffectsPanel in
	the guide's fixed reading order. Display selected/excluded commitments, source
	references, exact designated recipient/subject/body, effect IDs/links and
	expected/observed fields. Keep all review data read-only.

3. Build RunTimeline with the stable ingest, select, analyst, drafter, auditor,
	approval, execute, verify, and assess stages. Use declared stage/span,
	logical-call, model-attempt, and provider-attempt identities. Keep workflow,
	trace/process, outcome, and first-proposal assessments distinct; stage
	completion alone cannot light an overall reliability pass.

4. Compose the one-screen layout with Slack review link/status, stable dimensions,
	and text-plus-icon labels for pending, failed and unverified states. Implement
	the guide's desktop/tablet/mobile behavior and keyboard/focus rules. Do not
	create an approval control. Keep technical detail behind an accessible
	disclosure or side panel rather than crowding the primary decision.

5. Add component/accessibility tests for exact draft rendering, completed product
	with pending assessment, wrong expected/actual recipient, original draft
	failure despite corrected-plan success, failed partial, zero-label/0-of-0,
	offline/session states and no approval bypass. Add Playwright viewport checks
	at 375x812, 768x1024, and 1440x900; attach synthetic screenshots and hand U02
	the component props and fixture contract.
