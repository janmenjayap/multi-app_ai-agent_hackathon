## Sequential implementation steps

1. Freeze F02-shaped synthetic fixtures for waiting, blocked, partial, failed, completed, completed-with-unverified-assessment, and no-affected outcomes. Include zero human labels, missing provider fields, claim contradictions, and empty report denominators. Label all examples synthetic.

2. Build IncidentInput, EvidencePanel and PlanPanel to display selected/excluded commitments, source references and exact designated recipient/subject/body. Expose expected and observed artifact fields with missing/mismatched values, keeping review data read-only.

3. Build RunTimeline around actual declared stage/span and tool-attempt identities. Keep workflow status, trace/process assessment, independent outcome assessment and first-proposal quality distinct; stage completion alone cannot light an overall reliability pass.

4. Compose the one-screen layout with Slack review link/status and accessible labels for pending, failed and unverified states. Do not create an approval control. Keep technical evidence details behind a useful drilldown rather than crowding the operator's primary decision.

5. Add UI tests for exact draft rendering, completed product with pending assessment, wrong expected/actual recipient, original draft failure despite corrected-plan success, zero-label state and no approval bypass. Attach synthetic screenshots at recording size and hand U02 props/contracts.
