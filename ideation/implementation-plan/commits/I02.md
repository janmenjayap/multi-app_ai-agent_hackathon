## External-app integration to implement in this commit

Implement the [GitHub route/access mapping](../08-mcp-api-and-external-app-integration.md#3-github--i02)
in `src/server/adapters/github.ts` using I01 REST transport against
`https://api.github.com`. Source reads use `/repos/{owner}/{repo}` and
`/repos/{owner}/{repo}/issues/{issue_number}` plus only explicitly bounded
commit/deployment/workflow references. Find/create marked issue comments with
`GET`/`POST /repos/{owner}/{repo}/issues/{issue_number}/comments`; get/update with
`GET`/`PATCH /repos/{owner}/{repo}/issues/comments/{comment_id}`. Pin a tested
API-version header and preserve actual IDs/body/version/pagination metadata.

F01 validates `PG_GITHUB_TOKEN` and `PG_GITHUB_REPOSITORY`; R01 constructs this
adapter in `src/server/composition.ts`. Restrict the token to the disposable
repository: Issues read/write for these operations, plus read permissions only
for the technical reference families actually used. Record broader underlying
token permissions separately from the worker's narrow interface.

R01's `read_github_evidence` node calls this adapter and passes the complete
snapshot to B02's pure policy. B06 submits the exact approved comment after the
HubSpot/Gmail effects; B07/Q02 independently retrieve it and all marker candidates.
This adapter makes no LLM calls and is not handed to analyst/drafter/auditor.
An optional later MCP mapping replaces only transport under the same contract;
its actual server/tool names, schemas, and smoke evidence must first be verified.

**Handoff gate:** owned tests prove scope denial, complete marker lookup and
unknown-write behavior; `tools/smoke/github.ts` proves actual source read → marked
create → independent get → approved update → find when disposable access exists.
Deleting smoke artifacts is operator-only and not a worker capability.

## GitHub evidence handoff for reliability

Follow the [reliability plan](../06-agent-reliability-implementation.md)'s separation of sources, writes and independent observations.

1. Retain immutable repository/issue/comment IDs, exact relevant content, source version/digest, observation window and complete scoped pagination receipts. A mutable URL or display title cannot replace immutable identity.
2. Return all exact-marker candidates and their actual bodies, authors and linked artifact IDs. B06 adopts only a unique compatible effect; B07 and Q02 independently retrieve the chosen comment and dereference permitted cross-links.
3. Include comment create/update dispatches in I01's attempt stream with exact payload/response references. The adapter supplies observations and uncertainty, never authenticated approval or a semantic pass label.
4. Extend fixtures with a correct-looking comment on the wrong issue, a duplicate on a later page, stale source version, altered linked draft ID and a denied final read following successful creation.

**Additional acceptance:** the expected frozen engineering-impact content can fail independently of HTTP status, and unrelated issue/comment scope remains observable for Q02 protection checks. Hand over a sanitized receipt shape plus private actual smoke IDs when exercised; real model output and live workflow reliability remain separate evidence.
